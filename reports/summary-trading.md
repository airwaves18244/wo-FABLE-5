# Portfolio Review: trading-strategies + market-terminal-v3
(Sonnet subagent summary)

## 1. Purpose, domain, and relationship

**trading-strategies** (airwaves18244/Trading-strategies) is a pure-research corpus: 43 written specifications of non-HFT, economically-motivated trading strategies (momentum, carry, trend, arbitrage, volatility, event-driven, value, seasonality, crypto structure), explicitly scoped as "no code, no HFT, no indicator-only mechanics." It is the front end of a stated pipeline — research now, backtesting later — produced via a documented methodology (`flows/universal.md` from a separate referenced repo, `airwaves18244/REASEARCH-PLAN`, note repo name is misspelled "REASERCH-PLAN" in source).

**market-terminal-v3** (airwaves18244/Market-terminal-V3) is a desktop trading/analytics application (PRD + task plan only in this repo; no source code present). Its PRD is written in Russian and describes "Market Terminal V1–V2.5" as an already-existing Tauri desktop terminal (Finam Trade API + MOEX ISS/ALGOPACK data) that reportedly works end-to-end on mock/local data with domain math under test — but that prior codebase is not present in this repository or visible history; only V3 planning artifacts exist here. No reference to a product/repo named "Market-flow" was found anywhere in either repo — the connection between the two repos is topical/architectural, not code-linked: market-terminal-v3's `STRATEGY_FRAMEWORK.md` defines a strategy taxonomy (momentum/trend, swing/mean-reversion, breakout, stat-arb, futures arbitrage, carry, volatility/options, cross-sectional rotation) that maps closely onto trading-strategies' 10 categories — the terminal is plausibly the eventual execution/backtesting venue for strategies designed in the research repo, but no explicit cross-repo link, submodule, or shared file exists today. This is an inferred, not stated, relationship.

## 2. Content map — trading-strategies

Structure: `README.md` (nav), `SUMMARY.md` (Phase-5 final report with master comparison table + backtest priority order), `research/00-brief.md` (scope, 10 sub-questions SQ1–SQ10, inclusion criteria), `research/01-landscape.md` (~60 sources, H/M/L credibility-rated, organized by sub-question), `research/04-critique.md` (red-team pass: single-source-chain audit, cherry-picking check, independence/overlap audit, causal-leap check), and `strategies/` — 43 docs across 10 folders (arbitrage/RV 7, momentum 7, trend-following 3, mean-reversion/swing 4, carry 5, volatility 4, event-driven 5, value/factor 3, flows/seasonality 3, crypto 2).

Every strategy doc follows a fixed 8-section template (classification, economic rationale, signal/rules spec with parameter ranges, evidence with claim-ID citations, expected performance, failure modes, backtesting guidance, recommendations). Methodology is unusually rigorous for an AI-assisted research artifact: strategies are tagged by edge type (risk premium / behavioral / structural-flow / constraint), by decay status, and the corpus deliberately includes four "known-dead" strategies (S&P index-addition effect, pre-FOMC drift, naive overnight drift, Goldman-roll front-running) as an anti-cherry-picking control. The critique document explicitly discounts AQR-affiliated trend/carry evidence as "marketing-adjacent upper bounds" and reduces the headline "43 strategies / ~28-30 independent approaches" claim to "~10-12 effective independent bets" once stress correlations are considered — a self-aware, unusually honest quantitative caveat.

## 3. market-terminal-v3: planned scope

**PRD.md** (main branch, Russian) defines V3 as turning a working prototype into an active-trader-grade tool, benchmarked explicitly against TradingView (charting), Bookmap/ATAS/Sierra Chart (heatmap/footprint/order flow), CQG/MultiCharts (DOM trading, brackets), TSLab/Amibroker (walk-forward backtest), Bloomberg (linked workspaces), and OpenBB/LLM copilots (NL analysis). Non-goals: mobile, multi-broker beyond Finam+MOEX, sub-1ms HFT, social features, crypto. Eight epics (E1 data/connectivity, E2 charting/workspaces, E3 screening/alerts, E4 trading, E5 backtest/optimization research, E6 options, E7 LLM copilot, E8 platform/quality), six milestones M1–M6, explicit NFRs (≥50k ticks/s, p50 feed-to-pixel lag ≤100ms, ≤1.5GB memory/100 watchlist instruments, ≥90% domain test coverage).

The **plan branch** (`claude/trading-terminal-plan-x7dn0g`) adds 5 architecture docs (983 lines total, English): `ARCHITECTURE.md` (layered Rust workspace — domain/data/storage/app/front, Tauri 2 shell, DuckDB+Parquet storage, Svelte+TS frontend with Lightweight Charts/dockview/Canvas-WebGL, strict dependency rule that `domain` has no network/UI/DB), `MODULES.md` (14-module catalog mapped to PRD epics), `STRATEGY_FRAMEWORK.md` (JSON-configurable strategy schema, 8-class taxonomy nearly identical to trading-strategies' categories, lifecycle/promotion gates from backtest→paper→live), `DATA_SOURCES.md` (Finam gRPC/WS + MOEX ISS/ALGOPACK HTTP as first-class providers now, global-market providers deferred to an "M7 backlog"), and `LLM_LAYER.md` (multi-provider abstraction: Anthropic/OpenAI/Google/OpenRouter, task→model routing, redaction, cost control, degrade-to-local-fallback). `TODO.md` assigns every task to a named Claude model tier (Fable 5 = architect/reviewer for risk-critical and numerical-correctness work; Opus 4.8 = lead engineer for cross-layer/perf features; Sonnet 5 = bulk contract-driven implementation, 24 of ~70 tasks; Haiku 4.5 = mocks/docs/boilerplate) with per-task reasoning-effort levels (low/medium/high/max) — a notably granular AI-workforce allocation scheme.

## 4. Maturity: docs vs. code

Both repositories are **100% documentation/planning at present — zero application or strategy code exists in either repo as checked out.** trading-strategies is intentionally docs-only (explicit deliverable constraint: "no implementation code"); its own README states "Research complete. Next stage: backtesting (out of scope for this repo)." market-terminal-v3's gap is more consequential: the PRD asserts prior versions (V1–V2.5) already run end-to-end with tested domain math, yet none of that code is present in this repo or its branches (only two commits exist total: an initial "Add files via upload" with the 3 root docs, and the planning-package commit on the side branch). Either the V1-V2.5 codebase lives in an unlinked repository/location, or the "already working" claim in the PRD is aspirational/inherited boilerplate rather than verified fact — this cannot be confirmed from what's checked out. TODO.md's task list (T-1.1 through T-6.10, ~70 tasks) is entirely unstarted from what's visible; no branch shows implementation commits following the plan.

## 5. Quality / risk observations

- trading-strategies: strong methodological hygiene (explicit haircuts on all Sharpe estimates, decay tagging, single-source-chain flagging, deliberate inclusion of dead strategies) — above-average rigor showing genuine self-critique. Residual risk it names itself: selection bias toward *published* (hence partially arbitraged) strategies; crypto conclusions rest on <2 market cycles.
- market-terminal-v3: the PRD's ambition (Bookmap-grade heatmaps, tick-level backtesting, live order routing) is very large for a stated private-trader/solo project; NFRs are aggressive (60Hz UI, ≥50k ticks/s) and several architecture decisions (dockview, DuckDB, Canvas/WebGL order flow) are unvalidated by any prototype in-repo. The plan explicitly flags its own biggest risks: ALGOPACK/Finam contract drift, WebView heatmap performance, and live-trading-money risk (mitigated on paper by "paper parity first + risk engine + kill switch," but unimplemented). No CI, tests, or scaffolding exist yet.
- Cross-repo risk: the strategy taxonomy in STRATEGY_FRAMEWORK.md was seemingly authored independently of trading-strategies (different category names/counts, no cross-reference); reconciling the two taxonomies is unaddressed work.

## 6. Owner workflow signals

Heavily plan-first, AI-delegated style: both repos show a consistent pattern of **substantive content parked on non-default feature/research branches** while `main` stays empty or documentation-only. Branch names follow a `claude/<topic>-<random-suffix>` convention (Claude Code session branches). The TODO.md model-assignment table is a distinctive artifact — deliberate multi-model orchestration (Fable 5 / Opus 4.8 / Sonnet 5 / Haiku 4.5) with effort levels and definition-of-done baked into the plan. trading-strategies cites a reusable external "flow" methodology (REASERCH-PLAN/universal.md), suggesting a standardized repo-external research process applied across projects. Net picture: heavy upfront planning and research artifacts, produced fast and structured, with execution (actual code, actual backtests) consistently deferred.
