# SYNTHESIS — airwaves18244 Portfolio (10 repos)
(Opus 4.8 synthesis stage — integrates the four Sonnet analyst reports in this folder)

## 1. Portfolio map — the real project graph

There are effectively **three lineages plus two dead slots and one true outlier**, not ten independent projects.

**Product line A — the MOEX trading terminal (one product, four incarnations):** The same "Market Terminal" concept appears in four places at increasing fidelity. Its earliest checked-in copy is an *embedded, unrelated* `market-terminal/` Rust/Tauri tree living inside the C# `any`/RevitNvf repo (present only on the `claude/busy-gauss` branch, absent from `main`) — a scratch incubation. That was split out and matured into **Market-flow**, the only lineage member with real, CI-green code (~17k Rust + ~6.3k TS, phases 0–9 done). **Market-terminal-V3** is then a *fresh PRD + architecture restart* of the same product — Russian PRD benchmarking against Bookmap/TradingView/Bloomberg, plus five English architecture docs on a plan branch — that describes "V1–V2.5 already working end-to-end" but contains **zero code**. **trading-strategies** (43 strategy specs) is the research feed intended to populate the terminal's backtest/strategy modules. Critically, the analysts flagged that *no explicit code link exists* between any two of these: Market-terminal-V3's docs never name "Market-flow," trading-strategies never references the terminal repo, and V3's "already working" prototype is nowhere in its own history. The lineage is real but held together by topic and the owner's head, not by references, submodules, or shared packages.

**Product line B — the methodology stack:** **loop-plan** (abstract theory: generic agentic-harness templates + a self-education outer loop) sits above two near-identical concrete instantiations — **reaserch-plan** (research pipeline, 5 subagents, most built-out) and **dev-plan / dev-plan-arch** (software-engineering pipeline, PRD→SPEC→code→test→ship). trading-strategies explicitly cites reaserch-plan's `flows/universal.md` as the methodology that produced it — the *only* concrete cross-lineage usage link in the whole portfolio.

**Outliers / dead slots:** **star-club** (a Russian corporate HR bonus-scheme document) is genuinely unrelated. **Options** is completely empty (zero branches). **wo-FABLE-5** is the current empty work repo. `dev-plan` main and `Market-flow`/V3 mains are near-empty with content stranded on branches.

## 2. Cross-repo contradictions, duplication, drift

- **The terminal architecture is authored at least three times.** Market-flow's ROADMAP/SUMMARY, Market-terminal-V3's ARCHITECTURE.md/MODULES.md, and the embedded copy inside `any` each independently define the *same* layered Rust-workspace/Tauri-2/DuckDB/Svelte design. V3 re-derives a 14-module catalog and a strict "`domain` has no network/UI/DB" rule that Market-flow **already implements and CI-enforces**. This is a full architectural restart that discards a working, tested reference implementation rather than continuing it.
- **Two divergent strategy taxonomies.** trading-strategies uses 10 categories / 43 docs; Market-terminal-V3's STRATEGY_FRAMEWORK.md uses an 8-class taxonomy with different names and counts, authored with no cross-reference. The analyst explicitly flagged that reconciling them is unaddressed work — the research corpus and its supposed execution venue don't share a schema, so nothing in trading-strategies is machine-consumable by the terminal.
- **Frontend-stack drift within the methodology stack.** dev-plan-arch's opinionated multiplatform guidance mandates **React 18 + Zustand + TanStack Query**. The actual flagship product (Market-flow, and V3's own architecture docs) is **Svelte 5**. So the owner's own "how to build a multiplatform Tauri app" playbook contradicts the stack of the one real Tauri app in the portfolio. Either dev-plan-arch was never actually used for the terminal, or the terminal ignored it — evidence points to the former.
- **Methodology repos aren't referenced by the products that supposedly used them.** Only trading-strategies cites reaserch-plan. Market-flow and V3 carry their *own* `.claude/agents`, `.claude/skills`, TODO model-tier tables — reinventing the loop-plan/dev-plan-arch machinery locally rather than cloning it. loop-plan is the intended shared abstraction and is referenced by nothing.
- **Duplication inside the methodology stack itself.** reaserch-plan and dev-plan-arch reimplement the identical token-economy playbook, tiered-routing table, and escalation ladder with different vocabulary instead of factoring into a shared package.
- **Analyst contradiction to flag:** the market-flow analyst treats Phases 0–9 as genuinely done and CI-green; the trading/V3 analyst reports the V3 PRD's claim that "V1–V2.5 already work end-to-end" is *unverifiable from what's checked out*. These aren't strictly contradictory (they describe different repos), but the owner's V3 PRD is asserting maturity that only exists in a *different, unlinked* repo — a documentation-level overclaim the V3 analyst rightly distrusted.

## 3. Portfolio-level risks (ranked)

1. **Committed live-looking secret (Market-flow `.env`, `Finam_API_SECRET=tapi_sk_…`).** Tracked in git despite `.gitignore` listing `.env` and docs claiming it never enters the repo. Highest-severity, concrete, and directly contradicts stated intent — must be rotated and purged from history.
2. **Content stranded on non-default branches across the portfolio.** dev-plan main is a stub; Market-flow/V3/any keep real content on `claude/*` branches with empty/minimal `main`. Anyone cloning defaults finds nothing — a bus-factor and discoverability failure spanning 5+ repos.
3. **Plan/execution gap in Market-terminal-V3.** ~70 unstarted tasks, aggressive NFRs (≥50k ticks/s, ≤100ms feed-to-pixel), and unvalidated bets (dockview, Canvas/WebGL heatmaps, DuckDB) — with a working predecessor (Market-flow) it declines to build on. High risk of a second abandoned restart.
4. **Single-repo-as-scratchpad history (`any`/RevitNvf).** An entire unrelated Rust/Tauri project embedded in a C# Revit repo pollutes diffs and history; mixes a `.sln` and a `Cargo.toml` at one root. Precedent shows the owner's default is to dump then split.
5. **No shared taxonomy or contracts.** Diverging strategy taxonomies, no shared `AppError`/schema/data-contract package across terminal incarnations, no cross-repo references — every project re-derives foundations.
6. **Verification theater risk.** Extensive checkbox roadmaps quoting exact test counts, but no gate has ever fired in the methodology repos, no e2e/packaging CI on Market-flow, and stale top-level docs (RevitNvf README still says "no plugin code yet" with 8/8 steps done). Self-reported "done" is not uniformly trustworthy — precisely the failure mode the owner's own methodology forbids.

## 4. The owner's implicit operating model

A **tiered multi-model AI workforce driven by file-based, spec-first pipelines.** The recurring, load-bearing idea across the entire portfolio is "pay for reasoning, not volume": a fixed ladder — **Fable 5 / Opus 4.8** (architecture, numerical-correctness, security, synthesis, critique) → **Sonnet 5** (bulk contract-driven implementation) → **Haiku 4.5** (mocks, docs, boilerplate) — with per-task reasoning-effort dials (low/medium/high/max), a "fail-twice-then-escalate-with-a-written-summary" rule, and a hard prohibition on letting raw subagent output re-enter orchestrator context ("files are memory, context is scratchpad"). This is codified twice in the methodology repos and applied operationally in V3's TODO.md.

**What it's good at:** producing large volumes of internally-consistent, rigorously-structured planning and research artifacts fast (trading-strategies' methodological hygiene — decay tagging, deliberate dead-strategy controls, Sharpe haircuts, honest "~10–12 effective independent bets" caveat — is genuinely above-average). Clean ports/adapters architectures fall out naturally because the model tiering *forces* a domain/adapter split so cheap tiers can work on isolated pieces. Auditability and reversibility are first-class.

**Where it currently fails:** the model is *plan-rich, execution-poor.* Three of four methodology repos are 100% templates with `<placeholder>` fields; the most sophisticated template (loop-plan's self-education/skill-promotion loop) has **zero working instantiation**. The system spins up a fresh cold-start plan (new repo, new PRD, new architecture doc) instead of continuing prior work — hence four terminal incarnations and two strategy taxonomies. The tiering optimizes per-task cost but has **no portfolio-level memory**: nothing enforces reuse, shared contracts, or "did we already build this?" That is exactly the gap a top-tier reasoner is supposed to fill and currently isn't.

## 5. Candidate high-leverage decisions (for refinement by a stronger model)

1. **Consolidate the terminal lineage — continue Market-flow or restart as V3?** Top-tier because it's a one-way, months-long bet weighing a working CI-green codebase against a clean-slate PRD; wrong call wastes either sunk work or accumulated cruft.
2. **Define one canonical strategy taxonomy + machine-readable schema bridging trading-strategies ↔ terminal.** Top-tier: it's a cross-repo ontology decision that hundreds of downstream strategy docs and backtest modules must conform to.
3. **Resolve the Svelte-vs-React stack contradiction between dev-plan-arch and the real product.** Top-tier: a foundational platform commitment that invalidates one of two authoritative documents and constrains all future frontend work.
4. **Decide whether the methodology stack is a product or scaffolding — factor loop-plan into a genuinely shared, referenced dependency or delete the abstraction.** Top-tier: high-ambiguity architecture-of-the-architecture call that determines whether duplication compounds.
5. **Design the portfolio-level "prior-art / continuation" gate** that forces new work to reference existing repos before scaffolding a new one. Top-tier: this is the fix for the plan-rich/execution-poor failure mode; it's a workflow-invariant design, not a task.
6. **Secret-management and history-hygiene policy across all repos** (rotation, pre-commit scanning, branch-default convention). Top-tier: portfolio-wide security posture, get-it-wrong-once cost.
7. **Define shared cross-boundary contracts** (one `AppError`, data schemas, IPC command catalog) reused across terminal incarnations rather than re-derived. Top-tier: an API-design decision others execute against for months.
8. **Validate or kill V3's aggressive NFRs** (≥50k ticks/s, WebView heatmap 60Hz, Canvas/WebGL order flow) with a spike before committing 70 tasks. Top-tier: a feasibility/risk call that reshapes the entire epic plan.
9. **Decide branch-default / "main is truth" policy** to un-strand content across 5+ repos. Top-tier: affects discoverability, collaboration, and every future clone.
10. **Instantiate (or formally retire) loop-plan Template 2's self-education/skill-promotion loop.** Top-tier: it's the portfolio's most sophisticated unused idea; deciding if it's real capability or dead weight is a high-ambiguity research call.
11. **Reconcile the two independently-authored terminal architectures** (Market-flow's implemented layering vs V3's 14-module catalog) into one module map. Top-tier: merges two conflicting sources of truth.
12. **Establish a portfolio verification standard** so "done"/test-count claims are provable (e2e/packaging CI, doc-freshness checks) — closing the self-report gap the owner's own methodology demands but doesn't enforce. Top-tier: a cross-cutting quality-governance design.
